# 聆光手语——多模态无障碍沟通平台

## 8 分 40 秒演示视频：分镜、口播与录制说明

创作主线：以一次医院导诊沟通为故事，让观众跟随“表达需求 → 查证动作 → 听清安排 → 确认回复 → 持续学习”的过程理解产品。

推荐形式：网页实录为主，开头与结尾可出镜；摄像头识别保留真人操作；导诊声音由同伴配合，也可由演示者扮演。全片配完整中文字幕。

语气：平等、清楚、克制。介绍功能时说明用户解决了什么问题；让真正的识别结果、字幕和流式文字成为视觉中心。

目标时长 8:40，允许因真实模型响应在 8:20—9:20 内浮动。时间段包含鼠标操作、动作演示、结果阅读和静默等待，不要求旁白填满。

| 时间 | 内容 | 观众要看见的证据 |
| --- | --- | --- |
| 00:00—00:35 | 问题与故事 | 医院沟通中的时间、地点、材料 |
| 00:35—01:05 | 产品定位 | 高价值场景优先、10 个识别词 |
| 01:05—02:25 | 实时手语识别 | 关键点、你好、医院、稳定确认与词语记录 |
| 02:25—03:50 | 词典与 RAG | 原文、出处、原图、依据证据的回答 |
| 03:50—06:20 | 面对面沟通助手 | 真实语音转写、选中文字、流式摘要、回复朗读 |
| 06:20—07:55 | 学习与复习 | 加入计划、主动回想、反馈、当天重练和统计 |
| 07:55—08:20 | 技术支撑 | 浏览器、Flask、MongoDB、两类大模型任务 |
| 08:20—08:40 | 收束 | 四步使用过程与产品名称、网址 |

## 逐段分镜与可直接朗读的文案

### 01｜00:00—00:35：先让观众进入一次沟通

**画面与操作**

先用简洁片头显示“明天几点？去哪里？带什么？”，再切到医院导诊情境的演示者或产品首页。采用实拍、文字卡即可，不需要虚构医院后台或产品功能。

**口播**

> 明天几点到医院？去哪个服务台？需要带什么？
>
> 这些日常问题，对听障人士与健听人之间的面对面交流，可能意味着反复确认。
>
> 手语有自己的语法和表达方式，手势与书面语之间，也需要准确的理解。
>
> 聆光手语希望把表达、查证、理解和回应连接起来。接下来，我们用一次医院导诊沟通，看看它如何帮助双方完成交流。

**后期字幕**：让表达被看见，让信息被确认。

**导演提示**：开场不模仿听障人士的感官体验，不使用怜悯性措辞。把重点放在双方共享信息的需要上。

### 02｜00:35—01:05：讲清 MVP 选择

**画面与操作**

展示 HTTPS 地址与应用整体界面。轻扫侧栏，让“手语识别、问手语知识、沟通助手、手语学习”的位置可见。后期用一张轻量文字卡展示识别词表。

**口播**

> 聆光手语是一款多模态无障碍沟通 Web 应用。
>
> 第一阶段，我们采用高价值场景优先的 MVP 策略，围绕医疗、求助和日常交流，先做好“你好”“医院”“帮助”等十个核心词的识别。
>
> 这十个词限定的是当前视觉识别范围。词典查询、语音转写和沟通辅助，则共同支持后面的交流与学习。

**后期文字卡**

你好、谢谢、请问、医院、厕所、欢迎、帮助、报警、吃饭、再见。

**导演提示**：不必逐一念出十个词。字幕说明“当前手语识别词表”，避免被理解为词典和语音功能也只有十个词。

### 03｜01:05—02:25：用真实动作建立信任

**画面与操作**

1. 在“手语识别”页面点击“开启摄像头”，允许权限。镜头同时保留摄像头区域和右侧结果。
2. 手进入画面，让关键点连线清晰可见，停留约 3 秒。
3. 按已练习并符合项目词条示范的动作完整比划“你好”；待结果确认后留出约 3 秒阅读。
4. 保持同一动作或做自然小幅移动，展示确认期间的稳定显示与本轮记录去重。
5. 完整比划“医院”；等待确认，展示“本轮识别记录”中出现两个独立词语。
6. 若要重复录入同一个词，先将手移出画面超过约半秒，再重新完成动作。切换页面前关闭摄像头。

**口播**

> 首先，打开摄像头。手进入画面后，可以看到浏览器正在追踪手部关键点。
>
> 我先比划“你好”。系统会综合连续窗口的判断，确认结果后再显示。
>
> 这里请看右侧：确认后的词语会短暂保留，手部的轻微变化不会立刻把它替换掉。同一个动作，也不会不断重复写进本轮记录。
>
> 接着，比划“医院”。现在，记录里保留了“你好”和“医院”这两个已确认词。
>
> 这一阶段输出的是词语。自然手语包含语序、空间和表情等信息，因此系统保留确认结果，完整句意由沟通双方继续确认。

**后期字幕，按画面依次出现**

- 浏览器提取手部关键点。
- 连续窗口投票确认，结果锁定 1.5 秒。
- 仅记录稳定词语，不自动翻译成完整句子。

**导演提示**：防抖效果保留一段约 6—8 秒的连续实录。描述为“减少抖动、确认后短暂保留”，不要宣称在任何动作、光照下都不会闪烁。低置信度提示不是失败镜头必须隐藏的内容，但主片以清楚完成操作为目标。

### 04｜02:25—03:50：从一个结果走向有出处的理解

**画面与操作**

1. 手动点击侧栏“问手语知识”。输入“医院”，点击“查找”。
2. 依次停留：词条标题、原文说明、册号与页码或来源信息、原书插图。放大时保留图文对应关系。
3. 输入“医院怎么做？”，再次点击“查找”。展示回答区与下方证据区，圈出实际出现的来源编号或来源信息。
4. 此时先不加入学习计划，留到完成导诊沟通后再回来。

**口播**

> 识别之后，我们还需要查证：这个词的动作，具体应该怎样理解？
>
> 打开“问手语知识”，输入“医院”。这里可以看到词典原文、资料出处，以及对应的原书插图。
>
> 接下来，我再问：“医院怎么做？”系统会检索知识库，把找到的词典内容作为依据，交给大模型组织回答。
>
> 知识库结合了《国家通用手语词典》的 PDF 和 EPUB 资料，保留了词条、原文、来源和图片。对于 EPUB 内容，也保留章节锚点，方便追溯。
>
> 这就是 RAG，检索增强生成。用户读到解释，也能回到证据中核对；当资料不足时，系统会明确提示。

**后期字幕**：检索已审核词典 → 依据原文回答 → 对照出处与插图。

**导演提示**

- “医院”示例在项目资料中来自第四册 PDF。不要把这一条称为“来自 EPUB”。EPUB 是整个知识库的数据来源之一。
- 精确词命中属于有效检索路径，不要把所有查询都称为“向量检索”。自然语言也可能被归一化后精确命中。
- 正式录制前确认页面实际显示模型基于原文回答。若只显示“原书内容（模型暂不可用）”，这一镜只能说明词典检索，应在模型恢复后补录生成回答的镜头。
- 回答内容以实机为准，不预写手语动作解释，不杜撰页码、原文或模型回答。

### 05｜03:50—06:20：最高光——让面对面沟通形成往返

**A. 03:50—04:45｜把对方的声音变成字幕**

**画面与操作**

点击“沟通助手”，使用演示账号新建本次沟通，点击“开始收听”。由同伴通过电脑麦克风说出下方导诊台词。台词期间暂停解说，保留真实字幕逐步出现的过程。说完后结束收听，避免旁白或回复播报再次被转写。

**串场口播**

> 查证了词语，接下来回到面对面的交流。假设医院导诊人员正在说明下一次到院的安排。
>
> 我点击“开始收听”，让对方正常说话。

**导诊人员台词，模拟场景**

> 您好，下一次请您明天上午九点，到门诊楼二楼服务台，带上身份证和医保卡。到场后先取号，再等候叫号。如果找不到位置，可以请导诊人员帮忙。

**继续口播**

> 通过浏览器的 Web Speech 语音识别，对方说的话正在逐步显示为字幕。用户可以直接阅读，也可以在发现听写错误时修改文字。

**后期字幕**：语音 → 实时字幕 → 可核对文字。

**B. 04:45—05:30｜把长信息整理成可确认的重点**

**画面与操作**

在同一个语音框内选中刚才的整段转写，确认“已选择……个字”。点击实际按钮“总结重点”，完整保留至少 5—8 秒真实增量输出。待生成结束，分别标示时间、地点、所需物品。

**口播**

> 文字出现以后，长段说明里仍然有容易漏掉的信息。
>
> 我先选中这段字幕，再点击“总结重点”。AI 会针对选中的内容，逐步生成摘要。
>
> 我们要确认的三个重点是：时间，明天上午九点；地点，门诊楼二楼服务台；所需物品，身份证和医保卡。
>
> 原始字幕保留在这里，方便逐项对照。这样的整理，可以帮助用户更快找到下一步需要做的事。

**摘要的语义目标，供排练核对，不作为固定输出**

| 字段 | 必须来自导诊原话的信息 |
| --- | --- |
| 时间 | 明天上午九点 |
| 地点 | 门诊楼二楼服务台 |
| 所需物品 | 身份证、医保卡 |

模型也可能输出“先取号、等候叫号、找不到位置时求助”等条目。字幕可高亮这三类信息，不能把通用摘要包装成产品已有的固定三栏表单。

**C. 05:30—06:20｜让用户把回应说出来**

**画面与操作**

重新选中原始导诊字幕，点击“生成回复建议”。看完实际建议后，按用户意愿修改；需要保存时点击“存入语音框”。点击回复区域的“▶ 朗读”，留出完整播放时间，旁白与背景音乐让位于播报声。

**口播**

> 看清安排以后，用户还需要回应对方。
>
> 我重新选中刚才的字幕，点击“生成回复建议”。生成的文字是一份可以修改的草稿，用户确认自己的意思之后，再决定是否使用。
>
> 例如，我们可以把回复整理成一次礼貌的确认。

**供用户核对、编辑的回复示例**

> 谢谢，我确认一下：是明天上午九点，到门诊楼二楼服务台，带身份证和医保卡，对吗？

**播报后口播**

> 点击“朗读”，健听的一方就能听到这份回应。
>
> 对方说话，用户看字幕；用户核对重点，再用文字和语音回应。一次沟通，就有了清楚的往返。

**后期字幕**：听见对方 → 看清重点 → 确认回复 → 主动朗读。

**导演提示**

- 三个按钮的真实名称为“总结重点”“生成回复建议”“▶ 朗读”。后期可使用“AI 提炼重点”“AI 帮我回复”“语音播报”作为解释性字幕。
- 当前版本需要先在同一语音框中选择字幕，两个 AI 按钮才可用。第二次生成前重新选择，录制最稳妥。
- 摘要和回复的生成措辞、分条方式及等待时间均以实机为准。回复示例是用户可编辑的参考，不是模型固定答案。
- 如需压缩长等待，保留首字出现和一段真实流式过程，其余部分可用“等待片段已压缩”说明。不要加速到让观众误判真实响应速度。
- 本段展示医院沟通安排，不扩展成诊断、处方或治疗建议。

### 06｜06:20—07:55：把一次使用变成下一次准备

**画面与操作**

1. 回到“问手语知识”，从“最近搜索”或重新搜索打开“医院”。勾选对应词条，点击“加入今日学习计划”，保留成功提示。
2. 点击“手语学习”→“今日学习”；必要时点击“刷新计划”。找到“医院”学习卡。
3. 先回想并比划，再点击“查看动作说明”，对照原文和图片。
4. 演示一次“有点模糊”，展示“含稍后重练”的计划变化。卡片再次出现时，拍清“这个词还需要连续答对 2 次”的提示。
5. 按实际队列完成重练，连续两次选择“记得”，展示完成进度变化。
6. 打开“学习统计”，展示本次实际产生的练习次数和反馈记录。

**口播**

> 这次沟通结束以后，刚才查过的“医院”，也可以成为下一次更熟悉的表达。
>
> 我回到词典，勾选词条，点击“加入今日学习计划”。原文和插图会一起成为学习资料。
>
> 在今日学习里，我先尝试回想动作，再打开说明核对。如果这次“有点模糊”，系统会把它放回当天的练习队列，提示我继续巩固。
>
> 当前规则下，首次选择“有点模糊”，需要连续两次记得；如果首次选择“忘记了”，则需要连续三次。当天完成以后，再进入后续的间隔复习安排。
>
> 例如，新词确认记得后，安排三天后复习；复习通过，间隔再逐步拉长。这是参考遗忘规律设计的规则式复习，让反馈影响后面的学习节奏。
>
> 最后，学习统计会记录这次实际的练习和反馈。从这一次查词，到之后继续巩固，学习也就接上了。

**后期规则卡，明确标注“复习规则示意”**

| 实际学习状态 | 当前业务行为 |
| --- | --- |
| 当天首次反馈“有点模糊” | 当天重练，需连续 2 次“记得” |
| 当天首次反馈“忘记了” | 当天重练，需连续 3 次“记得” |
| 重练期间再次模糊或忘记 | 当天连续记得计数重新开始 |
| 新词当天完成 | 下次安排在 3 天后 |
| 已学词当天完成 | 按原间隔约 2.2 倍向上取整，并至少增加 1 天，上限 180 天 |

如用时间轴图，推荐写“新词完成 → 3 天 → 7 天 → 16 天”，标注“连续完成复习时的间隔示意”。这是复习间隔序列，不能画成实际累计日期，也不能标成系统测得的记忆保持率曲线。

**导演提示**

- 当前页面没有直接展示“下次复习日期”或个体遗忘曲线，主片用真实队列变化与统计说明反馈生效，用后期文字卡解释排期规则。
- 当前 `mongo_store.py` 会先完成当天巩固，再调用 `next_review(..., remembered, ...)` 计算间隔。技术文档表 4-4 与 `next_review` 独立函数中“新词忘记约 10 分钟、模糊 1 天”等规则，不能直接当成当前完整业务的按钮结果。
- 预留“医院”为未学习词，使用演示账号排练队列；不要修改电脑日期或伪造历史学习天数。若需要展示三个完整重练循环，可以后期压缩其中重复操作，保留变化前后的真实状态。
- 学习反馈来自用户选择，不宣称系统能从摄像头自动测出记忆程度。

### 07｜07:55—08:20：让技术解释体验

**画面**

用后期简图连接“原生 JS 浏览器 → HTTPS / Flask → 识别模型 / MongoDB / 大模型服务”。这是一张技术说明卡，不伪装成产品页面。

**口播**

> 这些交互由同一套 Web 架构连接起来：原生 JavaScript 负责页面、摄像头和语音交互，HTTPS 支持线上安全访问，Flask 承接推理和业务请求，MongoDB 保存词典与用户记录。
>
> 通义千问支持词典检索与证据回答，DeepSeek 负责沟通内容的摘要和回复建议。

**导演提示**：无需朗读特征维度、接口路径或模型版本。项目的视觉词分类由独立识别模型承担，不要把“医院”的识别说成大模型看摄像头。

**口播**

> 从手势被看见，到资料有出处；从对方的话被读懂，到自己的回应被听见，再到下一次练习。

> 聆光手语，让每一次确认，都离顺畅沟通更近一步。

## 录制前准备

1. 使用已登录的独立演示账号，沟通与学习功能按账号保存数据。保留空白新沟通和适合演示的学习队列，避开私人记录。
2. 使用已验证可用的 Edge 或 Chrome，先测试当前浏览器的 Web Speech、摄像头、麦克风和中文朗读。在线网页能打开，不代表这些设备和外部模型链路都已验证。
